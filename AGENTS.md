# Agent notes for viajante

## Where to edit

- `tfs` bytes, cabin, or occupancy in the Google Flights URL: `src/viajante/tfs.py`
- Compact shopping RPC encode/parse: `src/viajante/google_flights_rpc.py`
- Google CSS, consent, empty vs markup, sweep HTTP client: `src/viajante/google_flights.py`
- Routes, LCC buffer, nearby expand, or flight ranking: `src/viajante/flights.py`
- Booking URL, chips, or DOM cards: `src/viajante/booking.py`
- Hotel evidence filters or ranking: `src/viajante/hotels.py`
- Delays or retry classification: `src/viajante/orchestration.py`
- Chromium session: `src/viajante/browser.py`
- `--save` or the state directory: `src/viajante/storage.py`
- Flags or printed tables: `src/viajante/cli.py`
- Offline keep-or-revert bench: `src/viajante/bench.py`
- Graded prompt battery (quality contract): `src/viajante/prompt_plan.py`, `src/viajante/prompt_bench.py`
- Loop protocol: `program.md` (humans edit this to steer)
- Bench baseline: `bench-baseline.json` (update only when a human merges a win)
- Owned parse corpus: `tests/bench/`
- Graded prompt corpus: `tests/prompts/`
- Domain types or JSON keys: `src/viajante/models.py`
- Typical vs same-route calendar median: `src/viajante/typical.py`
- Raw card text to numbers/enums: `src/viajante/parsers.py`
- Offline IATA lookup: `src/viajante/airports.py`
- Cheapest-per-day calendar and flex window (calendar then one shop): `src/viajante/dates.py`
- Explore destinations from an origin: `src/viajante/explore.py`
- Owned trip total (flight fare + hotel stay): `src/viajante/trip.py`

`google_flights.py` owns URL building, consent, card parsing, typed provider failures, the sweep HTTP client, and `GoogleFlightsSource`. `google_flights_rpc.py` owns the compact shopping request and `wrb.fr` parse. `booking.py` owns Booking.com URL/chips, consent, card extract, and `BookingHotelsSource`. Session lifecycle lives in `browser.py`. `flights.py` and `hotels.py` are the search loops: pure and offline-testable outside the browser source. `trip.py` joins owned flight fare and hotel stay when dates overlap; it omits the sum if either side missed.

## Public contract

CLI: `viajante flights`, `dates`, `flex`, `explore`, `airports`, `hotels`, `trip`, `bench`. MCP (stdio): `search_flights`, `search_dates`, `search_flex`, `search_trip`, `search_explore`, `lookup_airports`, `search_hotels`. English fetch. Prompts any language. No implied home hub. Successful flights may carry `google_flights_url` (`booking_token` wins), `typical_eur` / `vs_typical` / `vs_typical_pct`, and `stops_compare`. `--nearby` is opt-in same-city IATA on `flights` / `dates` / `flex` / `explore` / `trip` (and the matching MCP tools; default off; open-jaw not rewritten; no invented codes). `--via` / `--exclude-via` parse then filter on owned `layover_city` / `legs[].layovers` (unknown layover cannot prove include or exclude; nonstops drop for include, stay for exclude; no invented via list). Named `--price-cap` is a local post-filter of owned EUR (index 7 stays `None`). Flex is calendar then one shop (miss = empty). Trip total is omitted if either side misses, dates do not overlap, or currencies differ. Nearby alternatives take the cheapest owned fare in that city group, not a sum. Never invent a fare, typical, token, via list, or price cap.

## Invariants

- Validate CLI input before starting Chromium. That includes rejecting departure dates in the past.
- Two flight fetch modes, one public contract. `sweep` is one Chrome TLS session (`curl_cffi`) reused across legs with HTTP/2 multiplex: POST the owned shopping RPC, parse `wrb.fr` itineraries, and fall back to the owned HTML card parser only if that compact parse misses. `detail` is the Playwright scrape. `--fetch {auto,sweep,detail}`: auto uses sweep for 3+ flight queries and detail for 1–2. If sweep returns empty or a block, fall back to detail once for those legs only and record `fetch_backend: sweep_then_detail`. Do not re-run successful sweep legs. Shopping `ErrorResponse` (unknown airport / invalid query) and owned Google markup drift fail immediately without Chromium. Do not silently mix backends across legs of one report unless that fallback fired.
- Sweep must not use the 4.5s browser delay (inter-query delay is 0). Sweep must work with no Playwright/Chromium install. One lazy Chromium per process, and only when detail actually runs. Flights block images, media, and fonts. Booking blocks images and media only (fonts stay; they can be required to render the list). Do not spoof a stale Chrome/macOS user-agent; use Playwright's Chromium UA for detail.
- Detail delays: 4.5s + up to 1.5s jitter between queries; 3 attempts with 8s exponential backoff + jitter; browser reset after each failed attempt.
- No flags to shorten detail delays or parallelize requests. Progress output is allowed and goes to stderr.
- Retry only what can succeed on a second try. Sweep HTTP retries empty/drift/5xx once after 50 ms; the happy path does not sleep. After that retry, `markup_drift` still fails without Chromium. HTTP 429 resets TLS, waits 50 ms, and continues remaining jobs on a fresh session (happy path still no sleep). A sequential remesure harness may still stop on 429. `no_results`, `rejected`, `blocked`, `markup_drift`, and `browser_unavailable` do not get a Playwright second attempt. Booking card-wait timeouts (`BookingResultsTimeout`, still `fetch_failed`) also fail immediately. Do not hammer Booking after a challenge page. Sweep empty or `blocked` may still fall back to detail once; `rejected` and `markup_drift` do not.
- Every offer keeps raw text beside parsed fields (`price`/`price_eur`, `duration`/`duration_hours`, `stops`/`stops_count`). Sweep and detail clocks are 24-hour `HH:MM`. 1-stop cards may also carry `layover_city` / `layover_hours`. One-way and packaged round-trip offers may also carry `typical_eur` (median of owned cheapest-per-day calendar prices for that same origin-destination, or the same packaged stay), `vs_typical` (`below` / `near` / `above`), `vs_typical_pct` (signed percent versus that median), and `typical_deal` (English one-liner). When that median exists, `cheapest_date` / `cheapest_eur` point at the cheapest owned day in the same window. Omit typical, vs_typical, vs_typical_pct, typical_deal, and the cheapest keys when the compact calendar misses, has fewer than three priced days, or the query is multi-city. Flex searches stamp typical/vs_typical from the flex window grid (including packaged `--nights`) when that grid has at least three priced days. Never invent a market average.
- Successful queries may also carry `stops_compare` (`nonstop` / `one_stop`) with the cheapest cabin fare in each bucket from the same eligible parsed set. Omit a side when that bucket is empty; omit the whole block when both are empty. Ranked `--top` may hide a slow 1-stop that still appears here. Never invent a fare.
- JSON output only with `--save`. Browser state lives outside the checkout (`VIAJANTE_STATE_DIR` or XDG state dir), and is always written to a temp file and renamed. Booking fetch failures dump `booking-last-failure.html` / `.txt` there for diagnosis; do not commit those files.

### Flights

- Sweep is the fast shortlist (owned shopping RPC, Chrome TLS session, HTTP/2 multiplex, HTML fallback, no Chromium). Detail is max evidence (Playwright, full card set, current delays). Keep EUR, `hl=en` for flights, ranked/fare sort, and the baggage buffer in both modes. Card parsing is owned by viajante and keeps raw stop/price labels. Hotels fetch the same way: `lang=en` / `locale=en-US`, English card evidence.
- The flight scrape locale is `hl=en` with `locale="en-US"` for stable rendered evidence and the existing JSON `locale: "en"` contract. Currency comes from `curr` (CLI/MCP `--currency`, default EUR), independently of `hl`. Country is optional `gl` (CLI/MCP `--country`); omit it when unset. Do not default `gl` to a home hub. Planner prompts may be any language; the plan still emits English IATA and English fetch locale.
- `max_stops` is 0, 1, or 2 per query; filtering follows each query's value. `--max-layover` / `--min-layover` (hours) filter connecting offers by layover on both sweep and detail; nonstops stay. `--via` / `--exclude-via` parse then filter connecting offers whose owned `layover_city` / `legs[].layovers` match those IATA codes (city name or code); there is no owned shopping-POST via slot. Unknown layover cannot prove `--via` (drop) and cannot prove `--exclude-via` (keep). Nonstops drop for `--via` and stay for `--exclude-via`. Never invent a via list. `--max-duration` drops offers whose elapsed time exceeds that many hours. Default trip kind is one-way. `ORIGIN-DEST:OUT:BACK` without `--trip` is sugar for two one-way queries (out then return). `--trip rt` / `round-trip` and `--trip multi` POST one packaged shopping request. `--nearby` expands origin or dest to owned same-city IATA and searches each as a labeled alternative (default off; named open-jaw airports stay; no invented codes). `adults`, `children`, `infants_in_seat`, `infants_on_lap`, and `cabin` are query fields (CLI `--adults` / `--children` / `--infants-in-seat` / `--infants-on-lap` / `--cabin`). Shopping constraints index 6 is `[adults, children, infants_in_seat, infants_on_lap]`. `--bags N` / `--carry-on` fill shopping constraints index 10 with the bags pair `[checked, carry_on]`; leave both unset (today's default) so that slot stays `None`. Index 7 is the price-cap hole; the RPC layout is unknown, so it stays `None`. Named `--price-cap` / planner `price_cap_eur` is a local post-filter of owned parsed EUR (inclusive) after parse, before `--top`. Unnamed stays unset. Never invent a cap or a fare.
- The baggage buffer is an input (`--baggage-buffer`, default 70 EUR), not a constant. A non-zero buffer implies `needs_bag_verify`. Default `--sort ranked` selects `--top` by fare+buffer and hides connections many times slower than the fastest nonstop or shortest offer. `--sort fare` / `--sort price` use fare; `--sort duration` uses elapsed time; `--sort departure` / `--sort arrival` use local clocks. `--airlines`, `--exclude-airlines`, `--alliance`, and `--exclude-alliance` ride the shopping request (segment field 8 / index 7) so the provider filters before parse. `--depart-window`, `--max-duration`, `--min-layover`, `--via`, `--exclude-via`, and `--price-cap` are local post-filters after parse, before `--top`. `--depart-window` accepts hours (`6-20`, whole end hour) or clocks (`06:00-20:00`). Airline include/exclude still post-filter detail/Playwright cards as a backup. Alliances have no member list here, so they are shopping-only. If compact shopping cards include checked/carry counts, parse them onto the offer and drop offers that contradict a bag request; omit those fields when the bytes have no count. `needs_bag_verify` stays only while bag counts are still unknown. Never invent a bag fee or a bag count. The ranked total must be visible when a buffer was added. Callers must verify baggage on Google Flights before booking.
- `viajante dates ORIGIN-DEST --from DATE --to DATE` is the cheapest-per-day table (date-grid RPC, 31-day cap) with an English compact week calendar and sparkline of owned daily prices. `--nights N` / `--trip rt` prices one packaged stay per outbound day. JSON `summary` (min/median/max, cheapest date, n_priced) is omitted when fewer than three days are priced. A compact calendar miss falls back to one shopping sweep per day on the same TLS session. `viajante flex ORIGIN-DEST --around DATE --flex N` uses that same calendar, then one shopping POST on the cheapest legal day (`--nights` packages the stay). A calendar miss or empty window is empty: no invented fare. Dates/flex shop (flex winning day, or dates sweep-fallback per day) passes the same owned `_normalize_offer` post-filters as `search_flights`: `bags` / `carry_on` / `via` / `exclude_via` / `airlines` / `exclude_airlines` / `price_cap_eur` / `depart_window`. Unnamed stays unset. Never invent a fare, bag count, via, cap, or clock. Compact date-grid cells have no departure clock and are not post-filtered; a named window that drops every shop offer leaves that sweep-fallback cell unpriced. `viajante explore ORIGIN --from DATE --days N` is the dest shortlist from the Explore catalog, then a priced `--top`. Dest pricing uses the same owned `_normalize_offer` post-filters as `search_flights` / dates-flex shop. Named bags / via / airlines / `--price-cap` / `--depart-window` drop destinations whose cheapest surviving offer contradicts (unknown price or missing clock cannot prove the filter). Compact Explore catalog places are not offers and are not post-filtered. Do not invent dests to fill a cap. `viajante airports QUERY` is offline IATA lookup. `viajante trip` / MCP `search_trip` is owned flight fare + hotel stay (omit the sum if either side misses, dates do not overlap, or currencies differ). Flight shop uses the same owned `_normalize_offer` post-filters as `search_flights` / dates-flex / explore dest pricing. Unnamed stays unset. Never invent a fare, bag count, via, or cap. `FlightQuery` rejects unknown codes. Successful queries may carry owned `google_flights_url` (`booking_token` wins when present; omit the field if encode cannot run). Never invent a fare, typical, token, or via list.
- The owned prompt→query planner maps occupancy (omit the field when the prompt has no count), alliance (no invented `ST`), `--depart-window` (dates/flex/explore/flights; unnamed and “morning” vibe stay unset), via/exclude-via IATA, bags/carry-on, and a named `price_cap_eur` onto `--price-cap`. Unnamed cap stays unset. Overnight IST `keep_connect` is still `require_overnight ∪ via`. Around/±N becomes `intent=flex` with a real window; cheapest week becomes `intent=dates`; packaged RT stays stay packaged.
- The low-cost carrier list is partial. Absence from it is not evidence that a fare includes a bag.

### Hotels

- Hotel prices are total-stay prices. Keep requested filters, applied chips, and observed card evidence distinct. `--source booking` (CLI default) is Playwright evidence; `--source google` is the HTTP shortlist. MCP hotel search defaults to Google. Booking ratings are 0–10; Google Hotels ratings are 0–5. Booking search URLs include `order=price`. Hotel reports carry `fetch_ms` / `fetch_backend` like flight reports. Drop non-property titles such as `closed`.
- Hotel searches require free cancellation by default. Only an explicit caller or CLI opt-out may include non-refundable stays. If `oos=1` is applied and the card does not mention cancellation, print `filter applied; card silent` — do not store `free` in JSON.
- `--compare-cancellation` runs two sequential Booking scrapes (free cancellation on, then off) and joins stays by title+address. Do not parallelize. If one query fails, print both results and skip the join.
- `lodging_kind` is observed card evidence (`entire_home` / `private_room` / `hotel` / `unknown`). If the card is silent, apartment in the title may infer `entire_home`. Do not infer `hotel` from the word hotel in the title. Do not claim cancellation, lodging kind, or unit counts when unknown.
- Callers must verify the final total and cancellation terms on Booking.com before booking.
- Other OTAs are not scrapers in this tree. After Booking, for 1–3 finalists, the viajante skill says to use the user's browser harness (Google the property; list official site, aggregators, and other hits as options, without preferring one). Unverified second opinion. Do not invent prices from snippets or write them into `--save` JSON.
- `viajante trip` / MCP `search_trip` run flights then hotels sequentially (one lock). When dates overlap and both sides return owned prices, print flight fare + hotel stay + sum. Hotel `price_basis` stays `total_stay`. Omit `trip_total` if either side missed, dates do not overlap, or currencies differ. Flight shop uses the same owned post-filters as `search_flights` (`bags` / `carry_on` / `via` / `exclude_via` / `airlines` / `exclude_airlines` / `price_cap_eur`; unnamed stays unset). Never invent a fare or a stay.

## Tests

Prefer the locked checkout workflow:

```bash
uv sync --locked
uv run python -m unittest discover -s tests -v
uv run ruff check src tests
uv run viajante bench
```

`viajante bench` is the offline keep-or-revert command. It runs the unittest suite plus `ruff check` / `ruff format --check`, then prints `gate` and `score_ms` (`tests_ms` + owned `tests/bench/` parse). No Chromium. No live Google unless `VIAJANTE_BENCH_LIVE=1`, and that extra `sweep_ms` is never the score. Read `program.md` before running a loop experiment.

`viajante bench --prompts` (or `VIAJANTE_BENCH_PROMPTS=1`) is the graded prompt battery: the quality contract, not `score_ms`. Smoke→brutal prompts are English with international origins (no implied home hub). Savage may be other languages; the plan still emits English IATA and English flight fetch locale. Deterministic tiers are offline against the owned prompt→query planner. LLM-as-judge is opt-in (`VIAJANTE_BENCH_JUDGE=1`) via DeepSeek `deepseek-chat` (`DEEPSEEK_API_KEY`, or `VIAJANTE_JUDGE_KEY` as override; optional `DEEPSEEK_MODEL` / `VIAJANTE_JUDGE_MODEL`). There is no single correct answer: the judge records `score_1_100` plus a one-line reason. Nested or broken judge JSON is recovered when both are present; `JUDGE_SYSTEM_PROMPT` is untouched. Unset key prints `judge: skip` and invents no score. The key lives outside the repo; never commit `.env` or secrets. Do not fold judge latency or live scrapes into `score_ms`. Each row prints `plan_ms`; the summary prints `plan_p50_ms` / `plan_p90_ms` / `plan_max_ms`. Optional live find-flights timer (`VIAJANTE_BENCH_SWEEP=1` or `--timeit-sweep`, first 8 planned IATA+date flights, HTTP `fetch=sweep`) is off by default and never the keep metric; skipped print is `sweep_ms:` blank. Keep baseline remains **97.9**. Last judged **95.7** is not a keep. Gate is suite + `fail:0`. `score_ms` is not the product trophy. A looping agent may not delete `tests/prompts/` to “win”. Humans may later gate easy-tier failures; do not silently gate insane/llm cases. `tests/prompts/holdout.jsonl` is an operator overfitting check, not in `manifest.json`; looping speed agents must not open it when choosing a hypothesis. `viajante bench --prompts --holdout` loads only that file.

`pip install -e .` still works, but `uv` is the reproducible path for this tree. Tests are offline. They must not launch Chromium or use the network. CI runs the suite on Python 3.10 through 3.14.

`tests/test_google_flights.py` pins owned TFS encoding, the compact shopping fixture → `RawFlightCard` seam, and HTML fallback. Test the owned boundary (`RawFlightCard`, typed empty/markup/block failures), not upstream HTML rewriting. `tests/test_booking.py` is the Booking page seam (`build_applied_filters`, cards, empty vs markup). `tests/test_hotels.py` is eligibility, ranking, and the search loop.

`tests/test_json_contract.py` and `tests/test_hotel_json_contract.py` pin the flight and hotel JSON shapes. `tests/test_trip.py` / `tests/test_trip_json_contract.py` pin the owned trip total. A renamed or dropped key is a breaking change for anything reading `--save` output. `tests/test_dates.py`, `tests/test_flex_json_contract.py`, `tests/test_explore.py`, and `tests/test_airports.py` cover the calendar window, flex pick-then-shop, explore catalog, and offline IATA lookup. `tests/test_mcp.py` imports FastMCP when the `mcp` extra is installed (`mcp>=1.6,<2`).

Stdio MCP: `uv sync --extra mcp` then `viajante-mcp`. Tools: `search_flights`, `search_dates`, `search_flex`, `search_trip`, `search_explore`, `lookup_airports`, `search_hotels`. No Streamable HTTP. Keep the one-search process lock.

## Trip-planning search strategy

When helping pick destinations (not a single named route/date), follow `.cursor/skills/viajante/SKILL.md` → **Destination triage**: shortlist by vibe and a rough price band for the origin the user named (the MAD weekend table is MAD-origin only; no implied home hub), scrape fixed natural dates first, and only then expand ±1 day on 1–3 finalists. Around/±N on a named route is `viajante flex`; cheapest week is `viajante dates`. Do not brute-force full date matrices across a long destination list in one run.

## Private-data boundary

This tree is the public export. Do not add scraped caches, CSVs, personal trip scripts or routes, reservation data, browser session files, or paths from a private repository. Heuristic price *bands* in the viajante skill are allowed; live scrapes and personal trip JSON are not. Never invent a fare, typical, token, or via list.
